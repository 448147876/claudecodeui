| 项 | 内容 |
|---|---|

| 目的 | 确认「多个普通账号的项目、会话、目录是应用层隔离的」，以及其他功能正常 |

## 1. 结论

| 问题 | 结论 |
|---|---|
| 账号之间的会话是否隔离 | **是**。列表、搜索、按会话 ID 读/改/删/fork、浏览器直接打开别人的会话地址，全部隔离 |
| 管理员创建账号时设置的目录是否生效 | **是**。文件浏览、读写、新建项目/会话、Agent API、聊天工作目录、斜杠命令、MCP/Skills、只读目录都限定在本账号目录；独立测试三轮共发现 8 类间接越界入口，均已修复，其中前 5 类经独立复测确认，后续修复由本地检查和变异测试证明（第 5 节） |
| 其他功能是否正常 | **是**。项目、文件、git、worktree、会话、搜索、终端、聊天通道、上传、MCP、管理员引导与账号管理，在网关后面逐项操作过 |
| 普通账号能否修改全局配置 | **界面和 API 不能**（方案 B）；**网页终端和 Claude 自己的工具能**（应用层隔离的已知范围，第 6 节） |

## 4. 独立测试发现的问题与处理

| # | 问题 | 级别 | 处理 | 回归场景 |
|---|---|---|---|---|
| 1 | 文件接口可以写 `.git/config`、`.git/hooks`，git 随后执行其中指定的命令，等于通过 HTTP 以共用的系统用户身份执行命令，绕过全部目录限制 | 严重 | 文件接口拒绝访问 `.git` 内部；网关给普通账号进程强制 `core.fsmonitor=false`（环境变量优先于仓库配置） | HARD-01、HARD-02 |
| 2 | Taskmaster 三个接口的 `fileName` 没有校验，`../` 可读写自己目录以外的文件 | 高 | 隔离模式下必须是不带目录的文件名 | HARD-03 |
| 3 | 克隆项目的来源可以填本机路径，把本机任意 git 仓库复制进自己的目录 | 中 | 隔离模式下只接受远程地址 | HARD-04 |
| 4 | `/tmp` 是只读根目录，所有账号都能列出并读取，含其他账号的任务输出 | 中 | 只放行 `<tmp>/claude-<uid>/<本账号编码>/…` | HARD-05 |
| 5 | MCP、Skills 没指定目录时落在共用的安装目录 | 低 | 默认改为本账号目录 | HARD-06 |

同时扩大了静态扫描的范围：除路径参数外，还扫描 `fileName`、`githubUrl` 参数（UPG-10），并新增「上游新增运行 git 的文件」提醒（UPG-12）。

为什么第一轮没有发现这些：之前的审核只覆盖「直接接收路径参数」的接口；这 5 处是通过文件名、仓库配置、克隆来源、共用临时目录间接越界的。

## 5. 独立复测

### 5.1 第一次复测（修复 5 个问题之后）

| 项 | 结果 |
|---|---|
| 1 `.git` 保护 + fsmonitor | 直连路径**通过**；但发现旁路：项目内的符号链接可以绕过 `.git` 的路径检查（见下） |
| 2 Taskmaster 文档名 | **通过**（`../`、单次/双重编码、反斜杠、绝对路径都被拒绝，合法文档名仍可用） |
| 3 克隆来源 | **通过**（本机路径、`file://`、相对路径、`ext::`、选项注入都被拒绝）；含换行/空格的地址当时被放行，但 git 自身会拒绝，实际不可利用 |
| 4 `/tmp` | **通过**（不能列出，不能读别人的，符号链接、`..`、大小写变体都被拒绝；读自己的正常） |
| 5 MCP 默认目录 | **通过** |

新发现：

| # | 问题 | 级别 | 处理 |
|---|---|---|---|
| A | 文件接口只比较路径字符串，不解析符号链接，所以项目里（克隆来的仓库可以带有）指向 `.git` 的链接可以绕过刚加的 `.git` 保护，写入会被 git 执行的配置；同一机制也让项目内的链接能读写删其他账号的文件。这就是之前记为「可接受限制」的 T-6，复测说明它的影响比当时估计的大 | 中高 | **已修复**：文件接口先解析符号链接再判断（补丁 #9），指向项目外或 `.git` 的链接一律拒绝；HARD-07 回归；T-6 不再接受 |
| B | 账号目录本身是 git 仓库时，worktree 创建失败后在工作区外留下空目录 | 低 | **已修复**：创建前先校验目标（补丁 #12）；API-07 现在断言工作区外没有任何残留 |
| C | 克隆来源含换行/空格的地址在入口处被放行 | 低 | **已修复**：含空白或控制字符的地址直接拒绝 |

另外确认：经文件接口写入的 `.git/hooks/*` 文件没有可执行位，hooks 类命令执行需要额外手段；代码里没有调用 `git submodule`、自定义 diff/merge/filter 驱动。

### 5.2 第二次复测（修复 A、B、C 之后）

| 项 | 结果 |
|---|---|
| 符号链接（指向 `.git`、指向其他账号、多层链接、父目录是链接、尚不存在的新文件、保存/新建/重命名/删除/上传/读取） | **全部通过**；指向项目内部的链接照常可用 |
| worktree | **通过**：创建前就拒绝，工作区外没有任何残留 |
| 克隆来源含换行、空格、控制字符 | **通过**：应用层在进度接口里就拒绝，没有启动 git |

测试员认为硬链接和「先检查再换成链接」的竞态需要终端级能力才能构造（文件接口不能创建链接），属于已接受的终端范围，不是新的 HTTP 通道。

新发现：

| # | 问题 | 级别 | 处理 |
|---|---|---|---|
| D | `/api/commands/execute` 对命令文件只做字符串比较，不解析符号链接；`.claude/commands` 下指向其他账号文件的链接会让对方文件的内容被当作命令内容返回（与 A 同一类问题，不同代码路径） | 中 | **已修复**：先解析符号链接，只放行用户级命令目录和本账号目录内的文件（补丁 #13，HARD-08） |
| E | `git.routes.ts` 的 `resolveRepositoryFilePath` 调用校验函数时没传根目录，实际只检查了空字节；目前靠 git 自己拒绝工作区外的路径才没有泄露（疑似，未复现出泄露） | 低 | **已修复**：隔离模式下每个候选路径必须在本账号工作区内（补丁 #14，HARD-09） |

### 5.3 主动排查同类问题

D 说明「读取项目里文件的地方各自只做字符串比较」是一类问题，所以没有等下一轮，而是把 `server/` 里读取项目内文件的地方都过了一遍：

| 读取点 | 处理 |
|---|---|
| 文件接口 | 已加固（补丁 #9） |
| 命令执行 | 已加固（补丁 #13） |
| Taskmaster 任务文件、PRD 文档 | 已加固（补丁 #15，HARD-10） |
| 命令列表 | 无需处理：上游扫描时符号链接本来就被跳过（HARD-10 验证） |
| `/memory` | 无需处理：只返回路径，真正打开文件走已加固的文件接口 |
| MCP 的 `.mcp.json`、Skills 的 `SKILL.md` | **未处理**，记为 T-8：只在「项目里有指向其他账号文件的链接」时才有影响 |

这一轮之后的修复（D、E 及 5.3）尚未再经独立测试员复测，目前由本地检查（HARD-08/09/10）和变异测试（M24～M27 全部被发现）证明有效。

## 6. 仍然存在的限制（已知，均已记录）

| 限制 | 说明 | 记录位置 |
|---|---|---|
| 网页终端和 Claude 自己的工具不受应用层隔离 | 所有账号同一个系统用户。可以读写其他账号的目录，也可以读写网关数据（账号库、签名密钥）从而提升为管理员。只有每个账号一个系统用户（方案 D）才能解决 | `01` 第 7 节 |
| T-4 | 目录名编码前缀相同、但不属于任何账号的目录（如 `/w/projA-tmp`），其对话记录可被只读查看 | `03` 第 14 节 |
| T-8 | 少数读取点（MCP 的 `.mcp.json`、Skills 的 `SKILL.md`）仍不解析符号链接，只在项目里有指向其他账号文件的链接时有影响 | `03` 第 14 节 |
| T-7 | Claude CLI 运行时会改写 `~/.claude.json`，可能覆盖同时在界面上保存的用户级 MCP | `03` 第 14 节 |
| 未知入口 | 静态扫描和变异测试只能证明「已知入口被覆盖」，不能证明没有遗漏；三轮独立测试一共发现了 8 类，说明审核有盲区；每一轮发现的又多是「同一类问题的另一条代码路径」 | — |

建议：如果以后账号会给不同的人使用，不要依赖应用层隔离，改用方案 D。
