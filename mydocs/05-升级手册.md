# 05 升级手册

合并上游新版本时按本文操作。对应需求 B-1～B-6。

---

## 1. 准备（只做一次）

```bash
git remote add upstream https://github.com/siteboon/claudecodeui.git
git fetch upstream --tags
```

开发环境需要 Node.js ≥ 22（项目 `.nvmrc` 为 `v22`）。

---

## 2. 合并步骤

```bash
# 1. 停止网关（Ctrl+C 或 kill <网关 pid>），确认没有遗留进程
cloudcli-multi backups          # 可选：看一下现有备份

# 2. 只合并版本标签，不合并 main（B-1）
git fetch upstream --tags
git checkout feat/multi-account
git merge vX.Y.Z

# 3. 解决冲突（见第 3 节）

# 4. 安装依赖并构建
npm ci
npm run build:multi

# 5. 跑检查（B-5），全部通过才算升级完成
#    有 Playwright 时加 --browser，并设置 CLOUDCLI_MULTI_PLAYWRIGHT_CORE、CLOUDCLI_MULTI_CHROMIUM
CLOUDCLI_MULTI_UPSTREAM_BASE=vX.Y.Z cloudcli-multi check --upstream-tests --browser

# 6. （可选，建议大版本升级时做）变异测试：逐个去掉保护，确认检查仍能发现
python3 gateway/check/mutation.py        # 约 25 分钟；输出「未被发现的变异：无」才算通过

# 7. 启动；第一次启动会自动备份并预检所有账号（A-7）
cloudcli-multi
```

`CLOUDCLI_MULTI_UPSTREAM_BASE` 用于 UPG-06：告诉检查脚本上游基线是哪个标签，以便比对改动过的上游文件。不设置时与 `HEAD` 比较（只适用于改动尚未提交的情况）。

---

## 3. 冲突处理

| 文件 | 做法 |
|---|---|
| `package.json` | `version` 等字段取上游值；保留我们新增的 `bin.cloudcli-multi`、`scripts.build:multi`、`scripts.multi`、`files` 中的 `gateway/` |
| `package-lock.json` | 取上游版本后执行 `npm install` 重新生成 |
| `.oxlintrc.json` | 取上游版本，再把 `server/shared/isolation.ts` 加回 `backend-shared-utils` 列表 |
| `04-上游文件改动清单.md` 第 1 节列出的调用点（共 15 个，另有 3 处扩展） | 保留上游的全部改动，再按清单重新加上 1～3 行（每处都带 `cloudcli-multi` 注释，便于搜索） |
| `gateway/`、`mydocs/`、`server/shared/isolation.ts`、两个新测试文件 | 上游不会改动，不会冲突 |

快速找到所有补丁位置：

```bash
grep -rn "cloudcli-multi" server/ --include=*.ts | grep -v /tests/
```

## 4. 检查失败时

| 失败项 | 含义 | 处理 |
|---|---|---|
| UPG-10 静态扫描 | 上游新增了接受路径参数的代码 | 逐条判断（见 `04` 第 3 节）：需要隔离的，在 `isolation.ts` 的基础上加调用点、补 BDD 场景；不需要的，写进 `04` 第 2 节并注明理由 |
| UPG-11 home 目录引用 | 上游新增了引用 home 目录的代码，可能是新的全局写入口 | 阅读新增代码：如果普通账号能通过某个接口写共用配置，就在 `gateway/proxy/member-policy.mjs` 中加拦截规则、在 POL-01 中补用例；确认无关后，把文件加入 `gateway/check/scenarios/extra.mjs` 的已审核清单 |
| UPG-12 git 调用 | 上游新增了运行 git 的文件。git 会执行仓库配置、hooks 里指定的命令 | 阅读新增代码：确认它运行在项目目录里时，成员进程已有的两道保护是否足够（文件接口不能写 `.git`；`core.fsmonitor` 被强制关闭）。需要时扩充 `isolation.ts` 或网关的环境变量；确认后把文件加入 `extra.mjs` 的 `REVIEWED_GIT_FILES` |
| UPG-06 改动清单 | 改了上游文件但没登记，或补丁文件没有引用 `isolation.ts` | 补登记，或检查补丁是否在合并时丢失 |
| UPG-04 上游测试 | 上游测试失败 | 脚本已对 `agent.routes.test.ts` 的偶发失败（`Unable to deserialize cloned data`）自动重跑一次；仍失败时，先在未打补丁的上游标签上跑一遍，确认是否为上游自身的问题 |
| `build:multi` 报类型错误 | 源码（非测试）有类型错误 | 构建脚本只放过 `tests/` 下的类型错误；源码错误必须修复 |
| 其他场景 | 隔离或网关行为变化 | 用 `cloudcli-multi check --keep` 保留临时目录，查看 `data/accounts/<账号>/server.log` |

---

## 5. 回滚

```bash
# 代码回滚
git reset --hard <合并前的提交>
npm ci && npm run build:multi

# 数据回滚（网关必须已停止）
cloudcli-multi backups
cloudcli-multi restore <备份名>
```

升级后第一次启动如果迁移失败，网关会自动用刚生成的备份恢复数据目录并退出（UPG-08），这时只需要回滚代码。

## 6. 已知限制（升级时留意是否被上游改变）

| # | 内容 |
|---|---|
| T-1 | 退出钩子依赖上游把 token 存在 `localStorage['auth-token']`。如果上游改了存储方式，AUTH-06/07b（jsdom）可能仍然通过，需要在真实浏览器里手工验证退出 |
| T-4 | 不属于任何账号、但编码前缀与某账号相同的目录（如 `/w/projA-tmp`），其对话记录可被该账号只读查看 |
| T-6 | 已修复：文件接口先解析符号链接再判断；合并上游时留意 `resolvePathInsideProject` 是否仍调用 `assertProjectFilePathAllowed` |
| worktree | 账号目录本身是 git 仓库时 worktree 无法创建（创建前即被拒绝，不留残留） |
| 上游构建 | 基线提交 `80fbeac1` 的 `npm run build` 因上游测试文件的类型错误而失败；请使用 `npm run build:multi` |
